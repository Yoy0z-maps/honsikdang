# WP-05a 모바일 UX 수락 보고서

- 대상: 지도 검색창의 AI 검색 전환, 해석 결과 안내 카드, 실패 시 일반 검색 대체, 비로그인 안내 (master plan v0.2 §5A, §8)
- 날짜: 2026-10-15
- 환경: Playwright Chromium (Pixel 7 UA, 터치) 360×800 / 390×844, 프로덕션 빌드, 로컬 Supabase + 합성 시드, **테스트 대역 해석기(fixture)** — 실제 모델 아님
- 스크린샷: `specs/mobile-ux/screenshots/WP-05a-mobile-{360,390}-{1-ai-input,2-ai-interpreted,3-ai-fallback}.png`

## 1. 기준별 결과

| 기준 | 결과 | 근거 |
|---|---|---|
| AI 검색은 같은 검색창에서 전환(별도 화면 없음), 전환 버튼 44px, `aria-pressed` | ✅ | e2e |
| 해석 중 상태 표시, 중복 제출 막기 | ✅ | 검색 버튼이 "해석 중…"으로 바뀌고 비활성 |
| 해석한 조건을 보여 주고 일반 필터로 적용(수정·삭제 가능) | ✅ | e2e: 안내 카드의 "일식 / 1인 10,000원 이하 / 조용함", URL 필터, "필터 3개 적용 중" |
| 반영하지 못한 조건과 지역 이름을 숨기지 않음 (Q40) | ✅ | e2e: "‘강남역’ 위치는 찾지 않아요", "반영하지 못한 조건: 영업 중" |
| 실패·잘못된 출력·시간 초과 → 일반 검색 대체와 이유 안내, 이전 조건 제거 | ✅ | e2e 3종 (시간 초과는 4초) |
| 비로그인: 로그인 안내 후 같은 지도 위치로 복귀 (Q41) | ✅ | e2e |
| 가로 넘침 없음 | ✅ | e2e |

## 2. 스크린샷 검토 메모

| 화면 | 확인 내용 | 조치 |
|---|---|---|
| 해석 결과 | 상단에 둔 안내 카드가 장소 제안(＋) 버튼을 가리고 닫기 버튼과 겹침 | 하단 시트 위로 이동(W5a-07) 후 재촬영 |
| 실패 대체 | 이전 AI 검색 조건(일식·조용함 등)이 남아 "필터 4개", 결과 0곳 | 새 AI 검색은 이전 조건을 지우도록 수정(W5a-06), e2e에 확인 추가 |
| 입력 | 긴 문장은 입력칸에서 앞부분이 가려짐 | 수용 (일반 검색창과 같은 동작) |
| 결과 0곳 | 합성 시드에 맞는 식당이 없어서이며, 안내 카드와 "필터 초기화"가 함께 보임 | — |

## 3. 수행하지 못한 확인

| 항목 | 확인 방법 |
|---|---|
| 실제 모델의 해석 품질과 지연 (K-35) | `ANTHROPIC_API_KEY` 설정 후 `npm run eval:parse` |
| 실기기 키보드에서 긴 문장 입력, 음성 입력 | 휴대폰에서 직접 입력 |

## 4. 판정

**UI는 통과, WP-05a 관문은 보류.** 화면 흐름과 대체 동작은 360·390 e2e로 확인했다. 관문(Q43)은 실제 모델 평가가 필요하므로 키 발급 후 측정한다.
