# WP-08 모바일 UX 수락 보고서 (사용 편의 개선 4건)

- 대상: 시작 시 위치 요청과 서울역 대체, 내 위치 표시·따라가기, 리뷰 별점·메뉴 가격, 장소 제안의 식당 검색 자동 입력
- 날짜: 2026-10-20
- 환경: Playwright Chromium (Pixel 7 UA, 터치) 360×800 / 390×844, 프로덕션 빌드, 로컬 Supabase, 위치 권한 허용(서울시청 좌표)·NAVER 키 없음(지도 자리는 안내 문구)
- 스크린샷: `specs/mobile-ux/screenshots/WP-08-mobile-{360,390}-{1-start-at-my-location,2-detail-rating-menu,3-review-rating-menu,4-suggest-search-results,5-suggest-filled}.png`

## 1. 기준별 결과

| 기준 | 결과 | 근거 |
|---|---|---|
| 시작할 때 위치를 묻고, 허용하면 내 위치에서 열림 | ✅ | e2e: 허용 시 ◎ 버튼 `aria-pressed=true`, 목록 기준 "내 위치에서" |
| 거부하면 마지막 지역, 없으면 서울역에서 열림 | ✅ | e2e: 거부 → URL이 서울역 좌표, 마지막 지역이 있으면 그 지역 |
| 내 위치 점과 정확도 원, 움직이면 따라감·지도를 끌면 멈춤 | ⚠️ 코드·단위 확인 | 실제 지도(NAVER 키)가 필요해 e2e로는 따라가기 버튼 상태만 확인 → 실기기 점검표 |
| 리뷰에 별점(필수)과 메뉴 가격(선택, 5개까지) | ✅ | e2e: 별 누르기, 메뉴 행 추가·수정 화면 채움, 반쪽 입력 서버 오류 |
| 상세에서 평균 별점, 리뷰별 별, 메뉴 가격(최근 방문 가격) | ✅ | e2e: 시청 국밥 4.5 · 2명, 순대국밥 9,000원 |
| 장소 제안에서 식당 검색 → 이름·주소·음식 종류·핀 채움 | ✅ | e2e: 결과 선택 후 각 칸 값과 핀 좌표, 결과 없음·오류 시 직접 입력 안내 |
| 360px 가로 넘침 없음, 44px 터치 영역 | ✅ | e2e 가로 넘침 0(리뷰·제안 화면), 별 44px, 검색 버튼·결과 `min-h-11` |

## 2. 스크린샷 검토 메모

| 화면 | 확인 내용 | 조치 |
|---|---|---|
| 리뷰 작성 | 별 5개와 "4점 · 좋아요" 문구가 한 줄에 들어감(360px) | — |
| 상세 | 요약의 평균 별점이 편안함 점수보다 먼저 보이고, 메뉴 가격에 방문일과 "지금은 다를 수 있어요" 안내 | — |
| 제안 검색 | 처음에는 검색 상자 제목이 "식당 이름으로 찾기"라 "식당 이름" 입력칸과 이름이 겹침(보조기기에서 혼동) | "검색으로 빠르게 채우기"로 변경 |
| 제안 채움 | 고른 결과의 음식 종류가 자동 선택됨, 모든 칸은 그대로 고칠 수 있음 | — |
| 시작 화면 | 키가 없는 환경이라 파란 점은 안 보임 | 실기기 점검표에서 확인 |

## 3. 수행하지 못한 확인

| 항목 | 확인 방법 |
|---|---|
| 실제 NAVER 지역 검색 응답(좌표 형식, 카테고리 문구) | 검색 키 등록 후 운영에서 2~3곳 검색 |
| 파란 점·정확도 원·따라가기(걷는 중), 화면을 끄면 위치 감시 중단 | `specs/ops/device-check.md` 위치 항목 |
| iOS Safari 위치 권한 문구 | 실기기 |

## 4. 판정

**코드 부분 통과.** 따라가기와 실제 검색 결과는 키 등록·실기기 점검 뒤 확인한다.
