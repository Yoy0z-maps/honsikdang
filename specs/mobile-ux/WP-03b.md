# WP-03b 모바일 UX 수락 보고서

- 대상: `/` 지도 우선 홈 (master plan v0.2 §5A)
- 날짜: 2026-10-15
- 환경: Playwright Chromium (Pixel 7 UA, 터치), 프로덕션 빌드, 로컬 Supabase + 합성 시드, **NAVER 키 비움**(지도 영역은 안내 문구로 대체)
- 스크린샷: `specs/mobile-ux/screenshots/WP-03b-mobile-{360,390}-*.png` (`SCREENSHOTS=1 npx playwright test e2e/screenshots.spec.ts`로 재생성)

## 1. §5A 수락 기준별 결과

| §5A 기준 | 결과 | 근거 |
|---|---|---|
| `/`가 바로 지도, 피드·목록 우선 화면 없음 | ✅ | e2e "opens on the map…": 지도 영역이 뷰포트의 80% 초과, 시트는 `collapsed` |
| 상단에 떠 있는 검색·카테고리 칩 | ✅ | 검색 입력이 화면 상단 15% 안. 스크린샷 1 |
| 현재 위치·재검색 컨트롤이 지도 위에 | ✅ (재검색은 실지도 수동 확인 필요) | 현재 위치 버튼 e2e. "이 지역에서 다시 검색"은 지도 이동이 필요해 자동화 불가 |
| 끌어 올리는 하단 시트 (접힘/절반/전체) | ✅ 탭·키보드 / ⚠️ 드래그 수동 | e2e "bottom sheet snaps…": 탭, ↑/↓. 드래그 스냅 계산은 단위 테스트(`nearestSnap`) |
| 마커 탭 → 간단 미리보기 | ⚠️ 목록 "지도" 경로로 확인 | 미리보기·상세 이동 e2e. 실제 마커 탭은 실지도 수동 확인 필요 |
| 시트 드래그 중 지도 제스처 방지 | ⚠️ 수동 | 헤더 `touch-action: none` + 드래그 시작 후에만 pointer capture. 실기기 확인 필요 |
| 필터는 하단 시트, 활성 표시, 한 번에 초기화 | ✅ | e2e "filter sheet…": 필터 칩 배지(`필터, 1개 적용 중`), 헤더 "필터 1개 초기화" |
| 위치 권한 없이 모든 흐름 동작 | ✅ | e2e "works without location permission" (권한 없는 기본 컨텍스트 전체) |
| 초기 카메라: 허용된 위치 → 마지막 지역 → 기본 | ✅ | e2e "initial camera" 2건 + 단위 테스트 |
| 지도 영역 기준 조회, 매 프레임 요청 없음 | ✅ | 영역 RPC(pgTAP 11건), 지도 이동 시 자동 조회 없이 버튼만 표시 |
| 카드: 거리 기준 명시, 표본 수·최신성, 지어낸 값 없음 | ✅ | "지도 중심에서/내 위치에서 …m", 리뷰 수·최근 방문·중앙값 표기 |
| 터치 영역 44×44 이상 | ✅ (측정한 컨트롤) | e2e가 검색, 필터, 카테고리 칩, 현재 위치, 시트 손잡이, 로그인의 박스를 측정 |
| 가로 넘침 없음 | ✅ | e2e 360·390 모두 `scrollWidth - clientWidth ≤ 0` |
| safe-area / `viewport-fit=cover` / 100dvh | ✅ 적용 / ⚠️ 노치 기기 수동 | CSS 변수 `--overlay-top`, `--sheet-collapsed`에 `env(safe-area-inset-*)` |
| 키보드가 입력을 가리지 않음 | ⚠️ 수동 | `interactiveWidget: resizes-content`, 검색 포커스 시 시트 접힘 |
| 동작 줄이기 | ✅ 적용 | `prefers-reduced-motion`에서 전환·애니메이션 제거 |
| 화면 낭독기용 지도 대안 | ✅ | 지도 region 라벨 + 시트 목록, 접힌 시트 목록은 `inert` |
| 360×800, 390×844 Playwright | ✅ | 32 tests 통과 (프로젝트 2개) |

## 2. 스크린샷 검토 메모

| 화면 | 확인 내용 | 조치 |
|---|---|---|
| 360 홈 | 검색 안내문이 잘렸음("…주소 검") | 문구를 "식당 이름·주소 검색"으로 단축 → 재촬영에서 해소 |
| 360 칩 줄 | 마지막으로 보이는 칩이 화면 끝에 정확히 맞아 가로 스크롤 단서가 약함 (390에서는 다음 칩이 일부 보임) | 개선 후보 UX-01 |
| 미리보기 | 접힌 시트 위에 카드, 상세 보기 44px | 첫 촬영은 시트 전환 중이었음 → 대기 후 재촬영 |
| 필터 전체 | 시트가 칩 줄 아래까지 열리고 검색은 계속 보임 | — |

## 3. 수행하지 못한 확인 (사용자 확인 필요)

| 항목 | 이유 | 확인 방법 |
|---|---|---|
| iOS Safari / Android Chrome 실기기 | 실기기 접근 불가 | 같은 Wi-Fi에서 `npm.cmd run dev -- -H 0.0.0.0` 후 휴대폰으로 `http://<PC IP>:3000` (NCP 서비스 URL에 해당 IP 등록 필요) 또는 배포 미리보기에서 확인 |
| 실제 NAVER 지도에서 마커 탭, 핀치, 지도 이동 후 "이 지역에서 다시 검색" | e2e는 키 없이 실행, 인앱 브라우저는 화면이 그려지지 않음 | localhost:3000에서 지도 이동 → 버튼 표시 → 결과 갱신 |
| 시트 드래그 중 지도가 움직이지 않음 | 실기기 터치 필요 | 시트 헤더를 위아래로 끌기 |
| 노치·홈 인디케이터 safe-area, 키보드 | 실기기 필요 | 검색창 탭 시 입력창·시트 가림 여부 |
| 저속 네트워크 | 미측정 | Chrome DevTools "Slow 4G"로 첫 화면·목록 로딩 확인 |

## 4. 판정

**통과 (사용자 확인 반영).** 자동화 가능한 §5A 기준은 모두 통과. §3의 실지도·실사용 항목은 2026-10-15 사용자가 직접 실행해 "잘 동작한다"고 확인함. 사용 기기·브라우저는 기록되지 않았으므로, iOS Safari와 Android Chrome을 각각 확인했는지는 출시 점검(WP-07)에서 다시 체크한다.
