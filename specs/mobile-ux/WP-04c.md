# WP-04c 모바일 UX 수락 보고서

- 대상: 상세 화면의 신고(식당·리뷰), `/admin` 검수 화면, 내 리뷰·내 제안의 운영자 사유 (master plan v0.2 §5A, FR-008)
- 날짜: 2026-10-15
- 환경: Playwright Chromium (Pixel 7 UA, 터치) 360×800 / 390×844, 프로덕션 빌드, 로컬 Supabase + 합성 시드(로컬 전용 관리자 2명)
- 스크린샷: `specs/mobile-ux/screenshots/WP-04c-mobile-{360,390}-{1-report-form,2-admin-reviews,3-admin-places}.png` (전체 페이지)

## 1. 기준별 결과

| 기준 | 결과 | 근거 |
|---|---|---|
| 신고는 리뷰·식당별로 열고 닫는 양식, 접수 확인 | ✅ | e2e: 리뷰 카드 안에서 사유·메모 → "신고를 접수했어요" |
| 로그인하지 않은 사용자의 신고 | ✅ 설계 | 서버 액션이 로그인으로 보낸 뒤 같은 상세로 돌아옴 |
| 관리자가 아니면 `/admin`이 404이고 제목도 안 보임 (Q31) | ✅ | e2e: 로그아웃 상태와 일반 사용자 모두 404, "검수" 제목 없음 |
| 검수: 승인, 사유 없이 반려하면 거부 (Q28) | ✅ | e2e: "이 동작에는 사유가 필요해요" → 승인 |
| 신고 해결 + 리뷰 비공개를 한 번에 (Q29) | ✅ | e2e: 해결 후 상세에서 리뷰가 사라짐 |
| 작성자에게만 사유 표시 (Q32) | ✅ | e2e: 작성자의 내 리뷰에 "운영자 사유: …", pgTAP: 다른 사용자는 볼 수 없음 |
| 44px 터치 영역, 가로 넘침 없음 | ✅ | e2e: 관리자 탭 44px, 가로 넘침 없음. 검수·신고 버튼은 모두 `min-h-11` |
| 버튼 접근성 이름 | ✅ | "식당명 승인", "식당명 리뷰 반려", "… 신고 해결" 등 대상을 포함 |

## 2. 스크린샷 검토 메모

| 화면 | 확인 내용 | 조치 |
|---|---|---|
| 관리자 대기 장소 | 중복 의심 후보가 영어 코드(`approved, very_close`)로 표시됨 | 한국어 라벨("공개, 20m 이내")로 변경 후 재촬영 |
| 관리자 탭 (360) | 마지막 탭("검수 기록")이 가로 스크롤 밖에 있음 | 수용 (가로 스크롤 가능), K-24와 같은 개선 후보 |
| 신고 양식 | 리뷰 카드 안에서 열려 대상이 분명함 | — |
| 상세 상단 "← 목록으로" | 링크 높이가 44px 미만 (WP-03 화면) | K-31로 기록, 다음 UI 작업에서 수정 |

## 3. 수행하지 못한 확인

| 항목 | 확인 방법 |
|---|---|
| 실기기에서 관리자 화면 사용성 (긴 대기 목록 스크롤, 키보드로 사유 입력) | 관리자 계정으로 휴대폰에서 `/admin` 사용 |
| 대기 항목이 100건을 넘을 때 | 현재 화면마다 100건까지만 보여 줌 (K-30) |

## 4. 판정
