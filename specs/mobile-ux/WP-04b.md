# WP-04b 모바일 UX 수락 보고서

- 대상: `/suggest` 장소 제안, `/me/places`, 지도 위 "＋" 제안 버튼 (master plan v0.2 §5A, FR-006)
- 날짜: 2026-10-15
- 환경: Playwright Chromium (Pixel 7 UA, 터치) 360×800 / 390×844, 프로덕션 빌드, 로컬 Supabase + 합성 시드, NAVER 키 비움
- 스크린샷: `specs/mobile-ux/screenshots/WP-04b-mobile-{360,390}-{1-form,2-blocked,3-needs-confirmation,4-created}.png` (전체 페이지)

## 1. 기준별 결과

| 기준 | 결과 | 근거 |
|---|---|---|
| 로그인 안 한 사용자는 로그인 후 같은 위치로 복귀 | ✅ | e2e: 지도 "＋" → `/login?next=/suggest?lat=…` (좌표 항상 명시) |
| 가운데 고정 핀 (Q24) | ✅ 구현 / ⚠️ 실지도 수동 | 핀은 지도 위 고정 오버레이, 위치는 지도 `idle`의 중심. 키 없을 때는 보던 지도 중심 사용을 안내 |
| 차단 / 경고 / 생성 3가지 결과 | ✅ | e2e: 같은 이름 같은 위치 차단 → 다른 이름 20m 이내 경고 → 확인 후 생성 |
| 차단 후 재시도 가능 | ✅ | 값 유지, 제출 버튼 활성 (작업 중 발견해 수정) |
| 다른 사용자의 검수 중 제안 비공개 (Q27) | ✅ | "이미 검수 중인 다른 제안이 N건 있어요" 한 줄, 이름·ID 없음 (pgTAP + 스크린샷) |
| 생성 후 리뷰 바로 쓰기 (Q26) | ✅ | e2e: 내 제안 → 리뷰 쓰기 → 해당 식당 리뷰 폼 |
| 미승인 장소는 지도 비공개 | ✅ | e2e: 지도 검색 0곳 |
| 44px 터치 영역 | ✅ | e2e가 이름·주소·종류·제출·뒤로 링크 측정 |
| 가로 넘침 없음 | ✅ | e2e 360·390 |
| 오류 안내 | ✅ | 필드별 오류(`aria-invalid`, `aria-describedby`), 한도 초과·서버 오류는 `role=alert` |

## 2. 스크린샷 검토 메모

| 화면 | 확인 내용 | 조치 |
|---|---|---|
| 제안 폼 (키 없음) | 지도 대체 문구가 탐색 화면용("결과 목록에서 확인")으로 맥락에 맞지 않음 | `NaverMap`에 `label`·`fallbackHint` 추가, 제안 화면 전용 문구로 변경 |
| 차단·경고 | 숨겨진 제안이 같은 문구로 여러 줄 반복 | 개수 한 줄로 묶음 |
| 생성 | 다음 행동(리뷰 쓰기, 내 제안) 44px 버튼 | — |

## 3. 수행하지 못한 확인 (사용자 확인 필요)

| 항목 | 확인 방법 |
|---|---|
| 실제 NAVER 지도에서 핀 맞추기 (지도 이동 → 제출 위치가 핀 위치인지) | `npm.cmd run dev` → 로그인 → 지도 "＋" → 지도 이동 후 제안 → 관리자 화면(04c) 또는 DB에서 좌표 확인 |
| iOS Safari / Android Chrome 실기기, 키보드가 입력을 가리지 않는지 | 실기기에서 이름·주소 입력 |
